The Graph Said “ok”. It Was Wrong.

Draft 5.0 fixed seven ways its code-graph tools returned well-formed, confident, wrong answers. For an AI agent, that is the worst failure a tool can have.

The Bottom Line

An agent cannot tell a wrong answer from a right one when both come back as valid JSON with "status": "ok". A crash costs a retry. A confident empty result costs a regression: the agent reads "impacted": [], concludes the change is safe, and ships it.

While preparing 5.0 we found seven places where Draft's graph tools did exactly that. None of them crashed. None of them raised a warning. Every one of them passed our test suite, because every graph test ran against a mock that returned what we believed the engine returned. The fix was not seven patches. It was a contract: an empty answer has to prove it is empty, and a missing answer has to say it is missing.

Why Silent Wrongness Is Worse for Agents

A human reading a blast-radius report that says “nothing depends on this file” for auth.h will squint. They know the codebase. An agent does not squint. It reads the field it was told to read and acts on it, at machine speed, across every task in the session.

That changes the cost model for tool errors:

FailureWhat the agent doesCost
Tool crashes, exit non-zeroNotices, retries or falls back to reading codeA few seconds and tokens
Tool returns an error fieldNotices if the prompt tells it to checkSame, if it checks
Tool returns a valid, wrong answerBelieves it, plans around it, cites it in reviewA bug that the review step was supposed to catch

The third row is the one that matters. A graph tool exists so the agent can stop guessing. If the tool guesses on its behalf and reports the guess as a measurement, the agent is worse off than with grep, because grep at least never claims to be complete.

The Seven Bugs

One was fixed in 4.0 and started the audit; the other six are fixed in 5.0.

1. Every query after the first read a stale index

The graph-*.sh wrappers indexed a repo the first time they saw it and never again. Every later query, including the blast radius /draft:implement computes right after the agent's own edits, came from the original index while reporting status: "ok". The agent asked “what did my change touch?” and got the answer for the code before its change.

Fix: wrappers re-index incrementally before every query. On an unchanged repo that costs about a tenth of a second.

2. File impact returned the file, not its dependents

graph-impact.sh --file was supposed to answer “what breaks if I change this file?” It returned the symbols defined inside the file, each listed twice, and only when the working tree had modified it. An unchanged file came back as an empty success. --file lib.sh also matched _lib.sh.

So the question an agent asks before editing a file, when the file is by definition unchanged, always got “nothing depends on this.”

Fix: --file now returns callers of anything defined in the file (up to --depth, default 3) plus the files that import it, with an exact path match.

3. A shapeless {} meant “no results”

When the engine returned an empty object, the wrappers treated it as a measured empty result: no callers, no cycles, no edges. An engine that failed to answer and a function nobody calls looked identical. (Fixed in 4.0, and the pattern that started this audit.)

Fix: a response without the expected shape is source: "unavailable" with exit code 2.

4. Hotspots past row 10,000 scored complexity 0

hotspot-rank.sh enriched each hotspot with complexity by scanning every node under LIMIT 10000. On larger graphs, a hotspot outside that window got zeros, and the enrichment field still said ok. The most-called function in a big repo could rank as trivial.

Fix: enrichment queries the hotspot symbols by name.

5. Cycles were counted once per rotation

cycle-detect.sh returned each 3-cycle three times (a→b→c, b→c→a, c→a→b), and a self-loop matched the 3-node pattern as (x, x, x). Run against Draft itself, that self-loop was the only “cycle” it found. Over-reporting is the mirror image of silent emptiness: the agent spends its budget on architecture problems that are not there.

Fix: rows that repeat a node are dropped; each cycle is reported once, rotated to its smallest member.

6. Two repos could share one index

The engine derives a project name by flattening / to -, so /x/a-b/c and /x/a/b-c mapped to the same database. Indexing one overwrote the other, and queries against either returned the other's graph with full confidence.

Fix: Draft names the project explicitly. A repo the engine already knows keeps its name; a new one gets <basename>-<sha8 of its path>.

7. The pinned engine version was never enforced

The fetch script exited early for any binary already installed, so bumping the pin never upgraded anyone. An off-pin engine on $PATH was used without comment. And the download was verified against a checksums.txt shipped in the same release as the archive, so a replaced release asset would have passed.

Fix: SHA-256 values for the pinned version's four platform archives live in fetch-memory-engine.sh. A version mismatch triggers a reinstall, and graph-preflight.sh warns on drift.

The Pattern: Absence Reported as Fact

Line the bugs up and they share one shape. Each time, the tool had no information, or the wrong information, and emitted the same bytes it would emit for a true negative. The engine didn't answer: “no callers.” The index was old: “ok.” The row was past the limit: “complexity 0.”

An agent needs three different empty answers, and 5.0's graph-impact.sh now gives it all three:

# Abbreviated. Known target, nothing depends on it. A true negative.
{"target": "scripts/tools/leaf.sh", "impacted": [], "status": "no-edges", "source": "memory-graph"}

# Target the graph has never seen: a typo, a path outside the repo, an unindexed language.
{"target": "scripts/tools/laef.sh", "impacted": [], "status": "no-match", "source": "memory-graph"}

# The engine did not answer. Exit code 2.
{"target": "scripts/tools/leaf.sh", "kind": "file", "impacted": [], "source": "unavailable"}

The difference between the first two is one extra query: when the dependents list is empty, the wrapper asks the graph whether the target exists at all. That query is the whole fix for bug 2's class of failure. An empty list is a claim, and the tool now checks the claim before making it.

The same rule covers truncation. impacted is capped at 200 entries so it fits in a context window, but downstream_files, affected_modules, and by_category are computed over the full set, and truncated: true says the list was cut. The agent never has to infer completeness from length.

Why the Tests Didn't Catch It

Draft had graph tests. Dozens of them. Every one used a mock engine, and every mock encoded our understanding of the engine's behavior. When that understanding was wrong, the mock was wrong in the same way, and the tests agreed with the code.

5.0 adds tests/test-engine-smoke.sh, which drives the wrappers against the real codebase-memory-mcp binary over a small fixture in an isolated cache: callers, freshness after an edit, file and symbol impact, cycles, hotspots, the query dialect, the calling convention, the snapshot marker, and the pinned version. A dedicated CI job fetches the pinned engine and runs it.

Against the pre-fix tools, it fails 8 of 12 checks, on code whose mocked suites were green.

Mocks are still the right tool for most of the suite: fast, deterministic, no network. But a mock tests your code against your beliefs. At least one test has to test your beliefs against the dependency.

Six Rules for Tools Agents Trust

None of this is specific to code graphs. Any tool an agent calls, whether an MCP server, a shell helper, or an API wrapper, is a candidate for the same failure. These are the rules Draft's tools follow now:

  1. Empty is a claim; verify it. Before returning “nothing found,” confirm the thing you searched for exists. Distinguish no results from no such target.
  2. Unavailable is an exit code, not an empty object. If the backend did not answer, say so in a field the agent is told to check and in the exit status.
  3. Refresh before read. A cache that is only built on first use is a snapshot. If freshness is cheap, pay for it on every query.
  4. Make truncation explicit. Cap lists for the context window, keep aggregates complete, and set a flag when you cut.
  5. Test against the real dependency at least once. One integration test in CI catches what a hundred mocked tests are structurally unable to.
  6. Pin what you download, and check the pin. Record hashes outside the release you fetch from, and reinstall on drift instead of trusting whatever is installed.

What Changed for Existing Posts

The May blast-radius walkthrough was written against the 4.x output shape and now carries a note saying so. The landing page's graph demos, which had been showing the retired output shapes, now match each wrapper's real 5.0 output.

Upgrade

# Reinstall the plugin; the fetch script now upgrades an off-pin engine
npx @drafthq/draft install claude-code

# Confirm the engine matches the pin
scripts/tools/verify-graph-binary.sh      # reports version and pinned_version
scripts/tools/graph-preflight.sh          # warns on drift

# Ask the question that used to lie
scripts/tools/graph-impact.sh --repo . --file path/to/file

If the answer is no-match, the graph doesn't know that file. If it's no-edges, nothing depends on it. If the exit code is 2, the engine didn't answer. In none of those cases will it say ok.

Full details are in the 5.0.0 release notes.
